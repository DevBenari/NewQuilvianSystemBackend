## 1. Masalah yang diperbaiki

Berkas sebuah kunjungan baru dapat dinilai lengkap bila jelas **dokumen apa yang wajib ada**
(`RM-DEC-045` syarat 3). Keputusan itu ditetapkan sebagai master yang diatur unit rekam medis —
bukan ditulis di program — supaya perubahan SOP tidak menuntut rilis. Tabelnya sudah dibuat
28 Oktober 2026, tetapi kosong dan belum dapat dikelola dari layar mana pun.

**Contoh:** komite rekam medis memutuskan Rawat Jalan wajib CPPT. Tanpa task ini perubahan itu
harus menunggu programmer. Sekarang petugas menambah kriteria "CPPT" pada profil `RJ` lewat
layar master, dan penilaian kelengkapan (`BE-39`) langsung memakainya.

## 2. Proses bisnis

**Tujuan:** sebelas profil awal tersedia sejak aplikasi menyala, dan unit rekam medis dapat
menambah, mengubah, serta menonaktifkan profil tanpa rilis program.

**Pelaku:** petugas atau kepala unit rekam medis yang punya izin `MedicalRecordCompletenessProfile`.

**Langkah:**

1. Saat aplikasi menyala, seeder mengisi sebelas profil awal bila belum ada.
2. Petugas membuka daftar profil, menyaring menurut jenis kunjungan, jenis unit, kondisi, atau status.
3. Petugas membuat profil baru: kode, nama, kunci (jenis kunjungan, jenis unit, kondisi), dan kriteria
   yang dipilih dari katalog.
4. Petugas mengubah profil: nama, kunci, dan seluruh kriterianya diganti sekaligus. Kode tidak berubah.
5. Profil yang tidak berlaku lagi dinonaktifkan. Tidak ada penghapusan.
6. Setiap perubahan tercatat di log dengan keadaan sebelum dan sesudahnya.

| Kriteria dibuang lalu dipilih lagi | Butir lama diaktifkan kembali; tidak pernah dihapus |

**Jalur tidak normal — dua petugas menyimpan kunci yang sama bersamaan.** Keduanya lolos
pemeriksaan aplikasi, lalu index unik di PostgreSQL (`NULLS NOT DISTINCT`) menolak salah satunya.
Yang ditolak menerima `409`, tidak ada yang tersimpan setengah.

**Seeder tidak pernah menimpa.** Profil yang kodenya sudah ada — termasuk yang sudah diubah atau
dinonaktifkan petugas — dilewati. Bila petugas sudah membuat profil dengan kunci yang sama tetapi
kode berbeda, profil awal itu juga dilewati.

## 4. Dokumentasi endpoint

#### Health Services / Master Data / Medical Record Completeness Profile

Base URL `api/v1/health-services/master-data/medical-record-completeness-profiles`

| Method | Path | Kegunaan | Hak akses |
| --- | --- | --- | --- |
| `GET` | `/filters/metadata` | Pilihan jenis kunjungan, jenis unit, kondisi, urutan, isian form | `MedicalRecordCompletenessProfile : Read` |
| `GET` | `/summary` | Jumlah profil total, aktif, nonaktif, dan aktif tanpa kriteria | `MedicalRecordCompletenessProfile : Read` |
| `GET` | `/` | Daftar profil: `search`, `isActive`, `encounterType`, `serviceUnitType`, `condition`, `sortBy`, `sortDirection`, `pageNumber`, `pageSize` | `MedicalRecordCompletenessProfile : Read` |
| `GET` | `/criteria/options` | Katalog 16 kriteria beserta artinya | `MedicalRecordCompletenessProfile : Read` |
| `GET` | `/{id}` | Satu profil beserta kriteria aktifnya | `MedicalRecordCompletenessProfile : Read` |
| `POST` | `/` | Membuat profil | `MedicalRecordCompletenessProfile : Create` |
| `PUT` | `/{id}` | Mengubah profil dan mengganti kriterianya | `MedicalRecordCompletenessProfile : Update` |
| `PATCH` | `/{id}/status` | Aktif atau nonaktif | `MedicalRecordCompletenessProfile : Update` |

Contoh permintaan membuat:

```json
{
  "code": "RJ-GIGI",
  "name": "Rawat Jalan Gigi",
  "encounterType": 1,
  "serviceUnitType": null,
  "condition": 0,
  "items": [{ "criterion": 4 }, { "criterion": 6 }]
}
```

Contoh kalimat jejak (`[AUD]`, kategori `HealthServices.MasterData.MedicalRecord`):

```text
Mengubah profil dokumen wajib RJ. Sebelum: nama 'Rawat Jalan', jenis kunjungan Rawat Jalan, jenis unit Semua jenis unit, kondisi Tanpa kondisi, status aktif, kriteria [InitialAssessmentAny, PrimaryDiagnosis]. Sesudah: nama 'Rawat Jalan Umum', …, kriteria [InitialAssessmentAny, ProgressNoteAny].
```
