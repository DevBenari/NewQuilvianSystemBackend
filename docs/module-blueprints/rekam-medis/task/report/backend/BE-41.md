## 1. Masalah yang diperbaiki

Dua puluh task amandemen sudah selesai, tetapi belum ada satu dokumen pun yang memberi tahu
pemakai apa yang berubah. Konsumen API — terutama layar frontend — tidak tahu:

- bahwa linimasa kini membaca seluruh modul;
- bahwa jenis 14 dan 15 tidak lagi kosong diam-diam;
- apa arti keadaan `Undetermined`;
- keterbatasan mana yang wajib tampil di layar.

**Temuan saat menyusun catatan rilis.** Kontrak `0.2.0` A1 mewajibkan field `unavailableKinds`
pada selubung respons `/timeline`. Ternyata field itu tidak pernah sampai ke klien sejak `BE-21`:

- Service menghitungnya, dan respons `/summary` membawanya.
- `MedicalRecordController.GetTimeline` membangun `MedicalRecordTimelineResponse` tanpa field itu.
- Uji kompatibilitas `BE-21` menserialisasi hasil service, bukan selubung HTTP, sehingga celahnya
  tidak terdeteksi.

Akibatnya layar tidak punya cara membedakan hasil Patologi Anatomi yang "belum tersedia" dari
pasien yang memang tidak punya hasil PA — persis kerusakan yang ingin ditutup amandemen ini.

## 2. Proses bisnis

**Tujuan:** pemakai API dan unit rekam medis tahu perubahan perilaku dan keterbatasan rilis
amandemen sebelum memakainya.

**Pelaku:** pemilik API (mengesahkan), pengembang frontend, unit rekam medis.

Catatan rilis disusun untuk pengembang frontend dan pengelola modul. Isinya: perubahan perilaku
endpoint berjalan, endpoint baru, aturan kelengkapan, hak akses baru, persiapan wajib,
keterbatasan, dan status persetujuan.
