## 1. Keadaan yang ditemukan di awal

Backend `BE-38` sudah menerima addendum ber-`purpose` `Attestation` (`2`) untuk catatan
`LockedUnsigned`: status catatan tidak berubah, dan satu catatan hanya dapat disahkan sekali. Di layar
berkas belum ada jalan untuk melakukannya:

- `medical-record-addendum-actions.jsx` hanya punya "Tambah addendum" (koreksi).
- `buildAddendumPayload` membuang field selain isi dan alasan, sehingga `purpose` tidak pernah terkirim.
- Panel dokumen tidak membedakan addendum pengesahan dari koreksi, dan tidak menyatakan catatan
  sudah disahkan.

Dua celah masukan ditemukan dan diputuskan pemilik modul sebelum kode ditulis (`RM-DEC-077`):

| Celah | Keputusan |
| --- | --- |
| Backend mewajibkan isi dan alasan untuk pengesahan, tetapi `RM-DEC-049` tidak menetapkan bunyinya | Terisi awal, tetap dapat disunting |
| Outcome menyebut layar "Catatan Saya Belum Ditandatangani", tetapi `/my-unsigned` hanya memuat `Draft`; `LockedUnsigned` hanya terbaca lewat `/my-authored` di luar kontrak `0.2.0` | Hanya layar berkas; layar "Catatan Saya" dicatat sebagai celah kontrak `0.2.1` |

## 2. Proses bisnis dari sisi pengguna

Dokter atau perawat membuka berkas pasien, lalu membuka catatan miliknya yang bertanda **"Terkunci,
Tidak Ditandatangani"**, yaitu catatan yang kunjungannya ditutup sebelum sempat ditandatangani:

1. Di bawah isi catatan muncul **"Sahkan isi catatan"** (tombol utama) di samping "Tambah addendum".
   Tombol hanya digambar bila server menyatakan pengguna berhak (`/authority`), catatan berstatus
   terkunci tanpa tanda tangan, dan belum pernah disahkan.
2. Modal pengesahan terbuka dengan isian terisi awal: pernyataan bahwa isi catatan benar, dan alasan
   bahwa catatan terkunci karena kunjungan ditutup. Penulis boleh mengubahnya.
3. Penulis menekan **Sahkan**. Tombol terkunci selama permintaan berjalan; klik ganda hanya mengirim
   satu permintaan.
4. Sesudah berhasil, detail dimuat ulang. Status keutuhan **tetap** "Terkunci, Tidak Ditandatangani",
   dan di bawahnya muncul keterangan "Isi catatan sudah disahkan … Statusnya tetap terkunci tanpa tanda
   tangan sebagai jejak." Addendumnya tampil bertanda "Pengesahan". Tombol Sahkan hilang.

**Jalur tidak normal:**

- **Pengganti penulis.** Bila server menyatakan pengguna sebagai pengganti sah, tombol berbunyi
  "Sahkan isi catatan sebagai pengganti" dan permintaan dikirim ke `/as-substitute`.
- **Tidak berhak.** Tombol tidak digambar; alasan dari server ditampilkan (perilaku `FE-04`).
- **`409`** (sudah disahkan, atau bukan catatan terkunci tanpa tanda tangan). Pesan server tampil apa
  adanya di modal, mis. "Catatan ini sudah disahkan sebelumnya."
- **Catatan `Signed`.** Tidak pernah menampilkan tombol Sahkan; koreksi tetap tersedia.

### 3.3 Kepatuhan arsitektur frontend

Tidak ada komponen, endpoint, atau state global baru. Aksi pengesahan memakai **komponen, modal
(`ConfirmModal`), pemeriksaan kewenangan, dan penjaga kirim-ganda yang sama** dengan koreksi
(`EXTEND`), sehingga dua aksi tulis permanen tidak punya jalur pengaman yang berbeda. Endpoint pengganti
tetap dipilih dari kewenangan server (`isSubstituteSubmission`), bukan dari mode form.

Lint pada berkas yang diubah: 0 galat. Satu peringatan `react-hooks/set-state-in-effect` pada efek
pemeriksaan kewenangan **sudah ada di HEAD**. Grep anti-regresi: nol warna literal baru, nol `<button>`
mentah, nol `!important`.
