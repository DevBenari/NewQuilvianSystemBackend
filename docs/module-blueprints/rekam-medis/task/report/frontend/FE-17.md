## 1. Keadaan yang ditemukan di awal

`BE-42` menambah kunci "jenis poli" pada profil dokumen wajib (`clinicType`, `clinicTypeOptions`,
saringan `clinicType`). Layar Profil Dokumen Wajib (`FE-13`) belum menampilkannya, sehingga profil
"Rawat Jalan Poli Rehabilitasi Medik" hanya dapat dibuat lewat seeder atau API.

## 2. Proses bisnis dari sisi pengguna

1. Petugas membuka **Tambah profil**. Isian **Jenis poli** tampil sesudah "Jenis unit layanan",
   pilihannya dari server, bawaan "Semua poli".
2. Bila **Kondisi** diubah ke selain "Tanpa kondisi" (misalnya Operasi), isian jenis poli
   **terkunci dan dikosongkan**, keterangannya "Hanya untuk profil tanpa kondisi." Kembali ke
   "Tanpa kondisi" membuka isian lagi tanpa memulihkan nilai lama diam-diam.
3. Simpan mengirim `clinicType` (angka) atau `null`. Profil berkondisi **tidak pernah** mengirim
   jenis poli.
4. Daftar menampilkan kolom **Jenis Poli** dan saringan **Jenis poli**; "Atur ulang filter" ikut
   mengosongkannya, dan paginasi kembali ke halaman 1 saat saringan berubah.
5. Penolakan server — misalnya `409` "Profil untuk kombinasi ini sudah ada: RJ-REHAB." — tampil apa
   adanya, form tetap terbuka dengan isian utuh.
