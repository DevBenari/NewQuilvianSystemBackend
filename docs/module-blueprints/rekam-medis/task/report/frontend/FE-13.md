## 1. Keadaan yang ditemukan di awal

Backend `BE-37` sudah menyediakan master profil dokumen wajib, yaitu delapan endpoint di
`api/v1/health-services/master-data/medical-record-completeness-profiles`, dan devYoga sudah berisi 11
profil hasil seeder. Di frontend belum ada layar, service, maupun entri menunya. Akibatnya, mengubah
daftar dokumen wajib hanya bisa dilakukan lewat Swagger atau seeder.

Hal-hal yang ditemukan dari source backend dan memengaruhi layar:

| Temuan | Akibat pada layar |
| --- | --- |
| Daftar hanya memuat `criterionCount`, bukan isi kriteria | Form ubah membaca rincian `GET /{id}` lebih dulu |
| `PUT` mengganti seluruh kriteria (full update); kode tidak dapat diubah | Form ubah mengirim semua kriteria terpilih; isian kode dikunci |
| `items[].sortOrder` tidak diterima (selisih A3 yang tercatat di `BE-37`) | Tidak dikirim. Kriteria diurutkan menurut nilai katalog |
| Enum terkirim sebagai angka (tidak ada `JsonStringEnumConverter` global) | Nilai dibaca sebagai angka; nama enum tetap dibaca bila ada |
| `UpdateStatus` dan simpan memicu `MarkIncompleteDueAsync`: penilaian yang belum `Complete` dinilai ulang pada putaran berikutnya | Layar menyatakan perubahan berlaku untuk penilaian berikutnya |
| Profil berunit menggantikan profil umum jenis kunjungan yang sama; profil kondisi menambah kriteria | Diterangkan di dekat isian kunci |

## 2. Proses bisnis dari sisi pengguna

Pengelola master membuka **Master Data → Pasien & Rekam Medis → Profil Dokumen Wajib**:

1. Tabel memuat semua profil: kode, nama, jenis kunjungan, jenis unit, kondisi, jumlah dokumen wajib,
   dan status. Profil tanpa kriteria bertanda **"Tanpa dokumen wajib"**. Di atas tabel ada ringkasan
   jumlah profil serta peringatan bila ada profil aktif tanpa dokumen wajib. Keadaan itu sah untuk unit
   Laboratorium dan Radiologi (`RM-DEC-060`), tetapi perlu terlihat supaya tidak terjadi tanpa sengaja.
2. Penyaring: kata kunci, status, jenis kunjungan, jenis unit, dan kondisi. Pilihannya diambil dari
   metadata server. Tombol ↻ mengosongkan semua penyaring.
3. **Tambah profil** membuka form berisi kode, nama, kondisi, jenis kunjungan, jenis unit, dan daftar
   centang dokumen wajib dari katalog server. Setiap kriteria disertai arti "terpenuhi"-nya. Profil boleh
   disimpan tanpa satu pun centang (kriteria 1), dan form menyatakan akibatnya.
4. **Ubah** memuat rincian profil. Kode terkunci. Kriteria dapat ditambah atau dilepas, lalu
   **Perbarui** mengganti seluruh daftar kriteria.
5. **Nonaktifkan** / **Aktifkan** meminta konfirmasi yang menerangkan akibatnya pada penilaian.
   **Tidak ada tombol hapus** (kriteria 3).

**Jalur tidak normal:**

- Server menolak simpanan (`VAL-RM-A04`–`A07`, kode kembar): kalimat server tampil apa adanya di dalam
  form, form tetap terbuka, dan isian tidak hilang (kriteria 2).
- Rincian atau katalog gagal dimuat: form menampilkan galat dengan tombol **Coba lagi**, dan simpan
  terkunci. Tanpa katalog, petugas tidak dapat melihat kriteria yang akan dikirim.
- Daftar gagal dimuat: galat dengan **Coba lagi**. Galat `403` menampilkan halaman tanpa izin.
- Server tidak terjangkau: "Server tidak dapat dihubungi. Periksa sambungan jaringan, lalu coba lagi."

### 3.3 Kepatuhan arsitektur frontend

Layar memakai komponen dasar yang sama dengan `FE-06` (`REUSE`): `AccessDeniedGate`, `Hero`,
`DataFilter`, `DataTable`, `ConfirmModal`, `BaseButton`, dan `Form` react-bootstrap. Tidak ada komponen,
state global, atau instance Axios baru. Galat diterjemahkan lewat `toMedicalRecordError` yang sama.

Validasi di layar sengaja hanya menyalin anotasi permintaan backend, yaitu isian wajib dan batas panjang
(kode 30, nama 150). Aturan `VAL-RM-A04`–`A07` **tidak ditiru**: keempatnya diputuskan server dan
kalimatnya tampil apa adanya. Meniru aturan itu di layar hanya membuka peluang ada dua kalimat berbeda
untuk satu aturan. Uji unit menjaga agar tidak ada kalimat tiruan di layar.

Lint pada berkas yang diubah: 0 galat. Tiga peringatan `react-hooks/set-state-in-effect` berasal dari
pola muat-daftar dan reset halaman yang sama persis dengan layar `FE-06`, yang juga punya peringatan itu.
Grep anti-regresi: nol warna literal, nol `<button>` mentah, nol `!important`.
