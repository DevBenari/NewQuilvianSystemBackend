# Mermaid Flowchart Contract

Use source-controlled Markdown and Mermaid syntax. Use stable business/system names, show relevant boundaries, and reference dependency IDs where material. Do not include low-level method or class clutter. Update a flow only when its architecture or relationship changes materially; do not create image artifacts.

Create a Module Context Flow when ownership or integration boundaries are crossed. Create a Business Process Flow when lifecycle, actor, approval, or state transition exists. Create a System / Integration Flow only for material API, event, or external integration.
